Advanced: pin vCPUs to specific host cores

Floating -- the default, and what we recommend -- lets the host scheduler run this VM's vCPUs on whichever physical core is free at the time. Home Assistant is bursty and mostly single-threaded at its core, so it gains far more from having any free core to run on than from owning a fixed pair. A VM pinned to specific cores cannot move away from contention: if a parity check or a transcode is hammering those same cores, a pinned Home Assistant is hammered right along with them, while a floating one just runs somewhere else. Pinning well also needs to know this host's SMT (hyperthread) pairings and cache/CCX boundaries, which most people have not measured. An earlier version of this container pinned every VM to host cores 0 and 1 by default -- but core 0 is where the Unraid host OS itself runs, so that pinned Home Assistant directly against the host's own workload.
